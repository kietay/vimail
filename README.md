# vimail

A native, local-first, vim-driven Mac mail client. SwiftUI + AppKit, SQLite, no Electron.
The UI follows the Figma Make design "Vim-based Email Client".

It runs on **Gmail** (REST API, OAuth) or on **dummy data**: a fake Gmail server with realistic mail
that never touches a real mailbox. Switch in Settings (`⌘,`) or the command menu (`:`).

## Run

Requires macOS 15+ and the Xcode Command Line Tools (full Xcode not needed).

```sh
make install  # release build installed to /Applications (Spotlight, Launchpad, Dock)
make run      # release build, packaged as build/app.noindex/vimail.app, then opened
make dev      # faster debug build, same place
make test     # unit + integration tests (store, sync engine, keymap, markdown)
```

`make install` quits a running copy, replaces `/Applications/vimail.app`, and registers it with
Launch Services. Run it again after pulling changes; your mail data is kept. `make uninstall` removes
the app (not the data). To keep it in the Dock: right-click its Dock icon → Options → Keep in Dock.

The icon is generated by `make icon` (`scripts/make-icon.swift`). It is full-bleed on purpose: macOS 26
masks full-canvas icons into its own squircle, but shrinks icons with transparent margins onto a grey plate.

`make` builds against the macOS 26.5 SDK because the Command Line Tools' macOS 27 SDK needs
Xcode-only macro plugins for SwiftUI. With Xcode installed, `make SDKROOT=` uses the default SDK.

## Gmail

**Connect:** Settings → Account → *Connect Gmail…* (or `:` → "Connect Gmail account"). Google sign-in opens
in your browser; vimail receives the answer on `http://127.0.0.1:<random port>` (OAuth loopback flow with PKCE).

- **OAuth client.** vimail uses your own Google Cloud OAuth client of type *Desktop app* (Gmail API enabled,
  your address added as a test user). The first sign-in asks for its `client_secret_….json`; vimail keeps a
  private copy as `google-oauth-client.json`.
- **Access.** The installed app asks for `gmail.modify`: read, labels, archive, trash and send. Not permanent
  deletion (Gmail empties Trash after 30 days), so "delete forever" is off for Gmail.
- **Sign-in expiry.** While the OAuth consent screen is in *Testing*, Google expires the sign-in after 7 days.
  The status bar then shows `signed out · sign in`; click it (or Settings → *Sign in again*). Local mail,
  drafts and queued changes are kept and sync after sign-in. Publishing the consent screen ("In production",
  no verification needed for your own use) or an *Internal* app in a Workspace org removes the 7-day limit.
- **First sync.** The inbox first, then the newest 1,000 conversations in the background (`caching N` in the
  status bar). It resumes after interruptions, and macOS does not throttle it (App Nap) while it runs.
  Changes then arrive through Gmail's history API every 30 s.
- **Quota.** Gmail limits API use per user per minute, shared by every client of your OAuth project. vimail
  learns the limit as it goes (starts slow, halves when Gmail says "rate limited", then creeps up) and lets
  your actions (archive, send, opening attachments) go before background downloads. The status bar shows
  `waiting for Gmail · rate limit` during a pause. An unverified project in testing measured about
  600–900 units a minute, far below the documented 15,000: check *Google Cloud Console → APIs & Services →
  Gmail API → Quotas → Queries per minute per user*. A conversation download costs 10 units.
- **What is local.** Drafts, snoozes, saved views, local labels and processor output stay on this Mac. Drafts
  saved in Gmail itself (web, phone) are not shown. Search covers the cached mail.
- **Signatures.** vimail adds the signature itself (the API does not). You can pick the one from your Gmail
  settings ("Gmail") or one of your own Markdown signatures (Settings → Compose). Settings sets the default. At the
  bottom of compose, the *Signature* checkbox turns it off for one message, and the menu next to it picks another
  one. Each draft keeps its choice. The compose preview shows the result.
- **Sending** builds a MIME message (text + HTML alternatives, attachments) and uploads it with the thread ID,
  so replies stay in their conversation. A retry after a timeout first checks Sent for the message's
  Message-ID, so a slow network does not send twice.

**Testing against real mail.** Debug builds (`make dev`) cannot change a real mailbox:

- they only ever ask Google for `gmail.readonly`, so Google rejects any change;
- every change and send goes to a dry-run log instead of Gmail (`accounts/<key>/dry-run/changes.log`, sent
  messages as `.eml` files);
- they keep their data in `~/Library/Application Support/vimail-debug`, apart from the installed app.

`VIMAIL_GMAIL_TOKEN_FILE=/path/to/token.json` makes a debug build use a token file from Google's own
libraries (for example the read-only `token.json` of `read_inbox.py`) instead of signing in.

## Logs

`~/Library/Logs/vimail/vimail.log` (debug builds: `~/Library/Logs/vimail-debug/`), rotated at 5 MB, three
files kept. Follow it with `tail -f`, or open it from the command menu (`:` → "Open log file") or Help →
Show Log File. The same lines go to the unified log (Console.app, subsystem `dev.vimail`).

It records: launch and account switches, each sign-in step, sync cycles and phases with counts and timings,
every Gmail request (method, path, status, size, duration, attempt), retries, rate limits and pacing,
token refreshes, outbox results, App Nap on/off. Never message content, subjects, other people's
addresses, OAuth codes or tokens.

## Keys

Vim-first. `?` shows everything in the app. The essentials:

| Keys | Action |
|---|---|
| `j` `k` · `gg` `G` · `^d` `^u` · `5j` | Move (counts work) |
| `h` `l` · `↵`/`o` | Focus list / reader · open (edits drafts) |
| `n` `p` · `J` `K` · `space` | Next/previous message in thread · next/previous conversation from the reader · page down |
| `e` `#`/`dd` `!` `s` `U` `I` | Archive, trash, spam, star, unread, read |
| `t` `m` `z` | Label, move, snooze (pickers; snooze takes `2h`, `3d`, `tomorrow 9am`, `mon`) |
| `b` | Quick snooze: no picker, until the time in Settings (default `tomorrow`, 8:00) |
| `v` `x` `*a` `*n` | Visual range, toggle one, select all/none |
| `u` `^r` `.` | Undo, redo, repeat last action |
| `c` `r` `a` `f` | Compose, reply, reply all, forward |
| `gi gs gt gd ga gz g# g! gA` `gl` | Go to Inbox, Starred, Sent, Drafts, Archive, Snoozed, Trash, Spam, All mail, label… |
| `H` `L` · `⌘⇧[` `⌘⇧]` · `gv` | Cycle Inbox + pinned views · manage views |
| `/` · `:`/`⌘K` · `^l` | Search (Gmail syntax) · omnibox · refresh + sync |

**Compose:** you write Markdown. The pane on the right shows the exact HTML recipients get.
`⌘↵` sends (with a 5s undo window, `u`). In To, Cc and Bcc, an address becomes a pill when you type `,` `;` or
the closing `>`, press `↵` or `tab`, or pick a suggestion. Click a pill to remove it; `⌫` in an empty field
removes the last one.

**Vim keys in the body.** `esc` goes to normal mode (block cursor, `NORMAL` in the status bar); `i a I A o O`
go back to insert mode. `esc` again leaves the body for the compose keys (`t` To, `s` Subject, `p` preview,
`i` back to the field), and `esc` once more closes and keeps the draft. In the To and Subject fields, `esc` goes
straight to the compose keys. Normal mode has the motions `h j k l w b e W B E 0 ^ $ gg G { } f t F T ; ,`
(counts work), the operators `d c y > <` with a motion or a text object (`iw aw iW aW i" a" i' a' i( a( i[ a[
i{ a{ i< a< ip ap`), `dd cc yy >> <<`, `x X D C s S Y J r ~ p P`, `u`/`^r` (undo, redo) and `.` (repeat). The
register is vim's own, not the clipboard; `⌘C`/`⌘V` still work. `>>` indents by 2 spaces (a nested list item).

**`^g` opens the body in your own editor** (`$VISUAL` → `$EDITOR` → `nvim`, from your login shell) inside the
compose panel, with your normal config. `:w` updates the preview, `:wq` returns to the body. Put mail-only settings in
`~/.config/vimail/vimrc` (sourced after your config), for example `set spell textwidth=0`.

**Read state:** a conversation is marked read after it stays selected for 1 second (Settings).
In read-filtered lists (Unread tab, unread views) it stays visible until you refresh (`^l`, switch tab/view).

**Search:** `from:` `to:` `subject:` `label:` `in:inbox|sent|trash|spam|snoozed|archive|anywhere`
`is:unread|read|starred` `has:attachment` `before:` `after:` `older_than:` `newer_than:` `"phrases"` `-exclude`.

## Where state lives

Everything is local:

```
~/Library/Application Support/vimail/
    settings.json                 preferences (theme, delays, editor, signature, account)
    session.json                  last mailbox/view, filter, cursor per mailbox, sidebar
    google-oauth-client.json      your Google Cloud OAuth client (mode 600)
    accounts/<account>/mail.sqlite   mail cache + full-text index, outbox, drafts, snoozes,
                                  saved views, local labels, processor results, contacts
    accounts/<account>/drafts/    draft attachments and vim buffers
    accounts/gmail-<email>/google-credential.json   Gmail refresh token (mode 600)
    dummy/server.json             the fake Gmail server's state
~/Library/Caches/vimail/attachments/   opened attachments (safe to delete)
~/Library/Caches/vimail/inline/        images embedded in messages (safe to delete)
~/Library/Logs/vimail/vimail.log        the log (no mail content)
```

`<account>` is `dummy` or `gmail-<email>`. Each account has its own cache, drafts and views.
Drafts, snoozes, saved views, local labels and processor output never leave this Mac.
Only mail actions (archive, read, star, labels, send) go to the provider, through the outbox.
Access tokens are never written to disk. The refresh token is a file only you can read; it moves to
the Keychain once the app has a stable signing identity (ad-hoc signatures change with every build).
`make reset-data` deletes it all. The omnibox has "Regenerate dummy mailbox".

## Architecture

```
Sources/
  MailCore       Models, MailProvider protocol, search parser, reply rules, MessageProcessor API
  MailStore      SQLite (WAL, separate reader/writer queues), FTS5 search, outbox, local-only state
  MailSync       MailActions (optimistic, undoable), SyncEngine (push outbox, pull changes), ProcessingCoordinator
  DummyProvider  Fake Gmail: labels, threads, history cursors, latency/failure simulation, incoming mail
  GmailProvider  Gmail REST API: OAuth (loopback + PKCE), threads, history, batchModify, MIME send, dry-run wrapper
  VimailKit      Vim key-sequence parser, Markdown → email HTML, fuzzy matcher
  Vimail         SwiftUI app: model, key router, views, reader (WKWebView), compose, embedded vim (SwiftTerm)
Vendor/SwiftTerm Terminal emulator for the embedded editor (MIT, trimmed, see Vendor/README.md)
```

- **Local-first.** The UI only reads SQLite. Actions write SQLite in one transaction and queue an
  outbox entry, so they are instant and work offline. The sync engine pushes the outbox (with backoff),
  pulls changes since a history cursor, and re-applies unsent local changes on top of provider state.
- **Providers.** `MailProvider` (`Sources/MailCore/MailProvider.swift`) mirrors the Gmail API: `labels`,
  `threads`, `history` cursors, `messages.batchModify`, `send` (raw MIME), attachments. `GmailProvider` and
  `DummyMailProvider` implement it; `AppServices` picks one per account. Nothing else knows which is in use.
- **AI classifier.** Implement `MessageProcessor` (`Sources/MailCore/Processing.swift`) and register it in
  `AppPipeline` (`Sources/Vimail/Model/AppServices.swift`). Processors run in the background on new mail
  (and `backfill()` for existing mail), once per message and version. Effects: add/remove labels
  (local-only by default), annotations, mark read, archive, star. `KeywordLabeler` is a working example.
- **Chat.** `MailStore` already exposes what a chat agent needs as tools: full-text `threads(query)`,
  `thread(id)`, `message(id)`, `contacts`, annotations. Actions go through `MailActions` for undo and sync.

## Debug scripting

Debug builds can replay keys through the real input path, for testing flows:

```sh
VIMAIL_SCRIPT='activate wait:1500 gi j j / type:coffee <CR> e' build/app.noindex/vimail.app/Contents/MacOS/vimail
```

`activate` brings the window to the front; `hide` hides the app (to test background behaviour).
`snapshot:name` saves the reader as `snapshots/name.png` in the data folder, and `name.json` with
which messages are expanded, focused and on screen. It needs no screen-recording permission and works
with the window in the background. Set `VIMAIL_HOME` to a scratch folder to test on fresh dummy data.
